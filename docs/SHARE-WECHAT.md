## 开头

45 天前，我开源了一个医疗辅助系统的第一版。

那时候它其实很「虚」：Python 认知服务能跑，但 Spring Boot 只是个没编译验证过的骨架，Vue 前端也只是个没构建验证过的骨架。README 里我老老实实写了「未编译验证」「未构建验证」，验证只有 17 项端到端用例。

今天再看：**112 个文件变更、+19825 行代码、38 次提交、版本 0.1.1**；四类角色、真数据库、LIS 对接、审核台、版本回滚，全部真跑通。

但这篇文章不想堆功能清单。**最值得讲的，是我们怎么发现「测试全绿」骗了自己**，以及为什么功能全做完之后，我把一个开关继续关着。

## 一、第一版和现在，差的不只是代码量

| | 第一版（9 月 21 日） | 现在（11 月 5 日） |
|---|---|---|
| 业务层 | 骨架，未编译验证 | 53 个 Java 类 + 真 PostgreSQL + 3 个数据库迁移 |
| 前端 | 单个页面骨架 | 登录 / 三栏工作台 / 医护后台，构建零错误 |
| 权限 | 只有认知侧的患者隔离测试 | 四角色 JWT，URL 级 + 资源级双层授权，越权一律 403 |
| 自学习 | 只在方案里，排在 P3 | 候选池 + 审核台 + 版本回滚已落地，还跑了一轮真实数据评测 |
| 验证 | 17 项 + 反例 | 14 套全绿，实测 97 / 19 / 81 / 26 / 71 项资产 |

架构上还改了一个关键决策：原计划要给框架补一组认知 HTTP 接口，最后换成「**Java 只做鉴权、校验、透传、留痕、落库，医疗算法只留在 Python 侧一份**」。

不是洁癖。这个项目真的因为「同源两份代码」坏过一次——相关性闸门只回植了其中一边，独立包发布版就开始答非所问。医疗场景里，两份实现悄悄分叉，约等于两份不同的医疗结论。

## 二、三个「不报错」的坑，比十个报错的 bug 更贵

做医疗系统最怕的不是崩溃，是**一切正常、结果是错的**。

**坑 1：装出来的包，功能全丢了。** `pip install` 之后所有医疗接口 404，但健康检查照样报 healthy。原因是一个注册能力只存在于没提交的工作区，而注册失败的代码还静默返回 0。现在的做法是：注册失败直接拒绝启动，健康检查里把「挂上了几条路由」报出来，另加一套专门跑「装出来的包」的冒烟测试。

**坑 2：后台数字看着很合理，其实是假的。** 「今日问诊量」永远不超过 200，一次问诊还被算两次——因为旧代码取「最近 200 条」在内存里筛。改成数据库带时间窗计数，并把口径定义随接口一起返回：**数字脱离口径，就没法核对**。

**坑 3：74 项联调全绿，真实数据一跑就露馅。** 这个最狠。

演示数据是我手工填齐字段的，所以联调一直绿。等到我真的开启自学习开关、让合成主诉完整走一遍「开始问诊 → 回答 → 结束」，才发现落库的就诊记录是**空壳**：Python 侧返回的是 `chief_complaint` 这类下划线字段，且按合规**不含任何诊断结论**，而 Java 侧读的是驼峰字段名——全是 null。结果就是：**候选池恒产 0 条，而且没有任何报错**。

修完字段对齐，又抓出第二个：分诊建议写的是「发热门诊 / 感染科」，而权限系统按单科室精确匹配，科室管理员对真实候选**一条都看不到**。

第二轮评测：**71 项通过，0 项失败**。同时给联调补了 7 项「真实链路落库」回归断言（74 → 81 项），专门防演示数据把空壳判成绿。

> 这里的方法论只有一句：**全绿不代表断言有效**。要故意把代码改坏，确认测试精确转红，再还原；要用真实链路跑真实数据，而不是只断言自己填的那几条演示记录。

## 三、功能做完了，为什么开关还是关着

自学习闭环是这一版最花心思的部分：从近期就诊抽候选 → 指纹去重 → 和现库冲突就挂起 → **审核台采纳才写进知识库并升版本** → 驳回不入库 → 知识池可回滚。绝不自动生效，绝不在线改权重。

但真实数据跑通之后，我确认了一件不太舒服的事：

**预问诊摘要按合规不含医师结论**，所以从就诊里抽出来的候选，正文实际是「患者自述 + 分诊建议」。这种内容，没有资格成为机构回答的依据。

于是做了两件事：给这类候选正文加了一行护栏「【预问诊采集·非医师结论，不得作为诊疗依据】」（注意**不放进检索标签**，否则等于给检索闸门新增一个可命中词，反而更容易被搜出来）；以及——**每日自动学习开关，生产继续关闭**。

护栏和人工审核都是兜底，不是根治。要真正打开它，得先补一条「医师确认后的判断/处置」采集链路。功能做完 ≠ 可以上线，这句话在医疗场景里是字面意思，不是客套。

## 四、还有哪些没解决（不粉饰）

- **合规**：规则表未经临床药师复核；未做医疗器械分类界定；等保、单独同意、导出审批、临床顾问与回顾性研究都还没启动。**MIT 只覆盖代码，代码开源 ≠ 可以合法用于临床诊断。**
- **功能边界**：影像只归档、不做分析（无三类证，这是刻意的）；中医知识库未开始；LIS 的 TCP 监听、HL7 ACK、术语映射未实现。
- **部署**：多主机水平扩容需要把会话存储接 Redis/数据库；生产要注入 JWT 密钥、接医院统一身份。
- **验证编排**：MCP 端到端、真实数据评测、分发形态冒烟是三套独立资产，还没编进日常一键验证；本轮也没有跑需要 Docker 的那两套。
- **文档卫生**（本轮已修）：四份文档里的验证项数还停在旧版本，同一份 README 一处写 67、一处写 81；源码里还嵌过一个裸 NUL 字节，让检索工具把 `.java` 当二进制。都已统一、已复验。

写得越细，越觉得**「把没做的事写清楚」比「把做了的事写漂亮」重要**。

## 结尾

第一版是「一份能自圆其说的方案 + 一个能跑的认知服务」。

这一版是「三端真跑通、四类角色、能对接检验系统、带审核台与版本回滚、并且被真实数据反复证伪过的 MVP」。

最花时间的不是那 19825 行代码，而是反复问自己三句话：这条断言写空了会不会照样绿？这份数据是不是演示数据填的、会不会盖住真缺陷？这个开关打开之后，出来的东西有没有资格进知识库？

**能回答这三个问题，比多写三个功能，更接近「可用」。**
