# 投产合规门禁清单（Go / No-Go）

> 生成日期：2026-11-06 · 适用对象：`pasm-medical` 0.1.1 · 状态：**未投产**
> 本文回答一个问题：**这个系统现在能不能进医院真实业务？答案是不能。**
> 配套的代码侧自检见 `backend/.../bootstrap/ProductionGate.java`；
> 本文只列**代码判定不了、必须由机构和人签核**的事项。

---

## 0. 先说清楚边界：代码能判什么，不能判什么

| 类型 | 例子 | 由谁判 |
|---|---|---|
| **机器可观测的配置组合** | JWT 密钥为空、演示账号开着、H2 内存库、MLLP 绑公网 | `ProductionGate` 启动自检（可自动） |
| **功能性合规闸** | 候选不含医师结论、AI 转人工、越权 403、审计留痕 | 自动化测试（131 项联调 + 74 项真实评测） |
| **机构流程 / 法律资质** | 器械分类界定、NMPA 注册、等保测评、伦理与回顾性研究、临床顾问复核、临床药师复核 | **只能由人签核，代码不能判，也不假装能判** |

把第 3 类伪装成一行绿色日志，比没有门禁更危险 —— 它会让「没做」看起来像「已验证」。
所以本文是一张**签核表**，不是一个能跑出 PASS 的脚本。

---

## 1. 自动门禁（机器判，投产前必须 `strict=true` 复验）

启动自检开关：`MEDICAL_PRODUCTION_GATE_STRICT=true`。
默认 `false`（只 WARN 不拦），因为本仓 dev / 嵌入式 PG 测试 / e2e 共用同一份默认配置。

| 检查码 | BLOCK 条件 | 处置 |
|---|---|---|
| `demo_login` | 写死的演示账号（`/123456`）启用 | 改接医院统一身份（OIDC/OAuth2 或签名 JWT），患者 ref 作为 claim 绑定 |
| `jwt_secret` | 密钥为空或 < 32 字节 | 注入 `MEDICAL_AUTH_JWT_SECRET`（`openssl rand -base64 48`），并配置轮转 |
| `learning_auto` | `MEDICAL_LEARNING_AUTO=true` | 生产关闭；候选须来自 `PHYSICIAN_CONFIRMED` 就诊且经审核台人工采纳 |
| `mllp_token` | 开了 MLLP 直连却没配 `MEDICAL_LIS_TOKEN` | 配令牌；通道本身 fail closed，但该状态必须被运维看见 |
| `mllp_bind` | MLLP 绑非回环地址 | 由院方网络管理员确认专网/白名单；本项目不代替院方做网络准入 |
| `database` | 数据源是 H2 | 切 PostgreSQL + Flyway 版本化迁移，`ddl-auto: validate` |

复验命令：

```bash
cd backend
MEDICAL_PRODUCTION_GATE_STRICT=true \
MEDICAL_AUTH_JWT_SECRET="$(openssl rand -base64 48)" \
MEDICAL_LIS_TOKEN="$(openssl rand -base64 48)" \
MEDICAL_AUTH_DEMO_LOGIN=false \
MEDICAL_DB_URL=jdbc:postgresql://<host>:5432/pasm_medical \
java -jar target/pasm-medical-backend-0.1.1.jar
# 期望：启动成功且日志「投产门禁自检：无 BLOCK 项」；
#       少配任一项 → IllegalStateException 阻止启动。
```

> ⚠ 上表只保证「配置没带病」。**它不证明系统可用于临床。**

## 2. 人工签核清单（代码判不了，必须逐项签字）

| # | 事项 | 当前状态 | 责任方 | 为什么必须 |
|---|---|---|---|---|
| 1 | **医疗器械分类界定**（是否属于 SaMD、几类） | ❌ 未启动 | 法规/注册事务 | 直接决定后续所有路径；本系统含分诊建议与知识库问答，存在被判定为二类/三类的可能 |
| 2 | **NMPA 注册 / 备案**（如适用） | ❌ 未启动 | 法规/注册事务 | 未取得注册证不得作为医疗器械用于临床诊断 |
| 3 | **等保测评**（预计三级）与定级备案 | ❌ 未启动 | 信息科 + 测评机构 | 涉及患者健康数据，属敏感个人信息 |
| 4 | **数据安全与个人信息保护影响评估**（PIA） | ❌ 未做 | 法务 / 数据合规 | 病历、过敏史、用药均为敏感个人信息，需明确告知同意与最小必要 |
| 5 | **临床顾问 / 医师团队复核知识库内容** | ❌ 未做 | 医务科 + 临床科室 | 现有知识库是演示资料；审核台只保证「有人点采纳」，不保证「内容正确」 |
| 6 | **临床药师复核中药十八反/十九畏规则** | ❌ 未做 | 药学部 | `safety` 模块的规则是教材级示意，不能作为处方拦截依据 |
| 7 | **回顾性 / 前瞻性临床评价与伦理审查** | ❌ 未做 | 伦理委员会 + 临床科室 | 需要真实数据证明安全性与有效性；合成数据评测（74 项）只证明链路不空壳 |
| 8 | **责任边界与知情同意文案** | ❌ 未做 | 医务科 + 法务 | 系统定位为「预问诊辅助」，不出诊断结论；需向患者明确 AI 参与和转人工路径 |
| 9 | **审计日志独立存储与留存策略** | ⚠ 部分（同库） | 信息科 | 当前 `ai_audit` 与业务同库；生产应独立库、只授予 INSERT、明确留存年限 |
| 10 | **应急处置预案**（AI 误答 / 停机 / 数据泄露） | ❌ 未做 | 医务科 + 信息科 | 需定义降级到纯人工流程的开关与演练记录 |
| 11 | **模型/知识版本回滚演练** | ⚠ 有功能未演练 | 信息科 | 审核台有版本回滚，但未在准生产环境演练过 |
| 12 | **多主机会话共享** | ⚠ 未做 | 架构 | `SessionStore` 为单机内存；扩容需接 Redis/DB，否则坐诊会话跨实例丢失 |

## 3. 刻意不做（做了反而违规）

| 项 | 决策 | 依据 |
|---|---|---|
| 影像自动分析（读片/给结论） | **不做**，只归档 + 转交 | 无三类证；自动读片属高风险诊断行为 |
| 中医知识库（P4/P5） | **不做** | 内容需临床药师逐条复核，当前无签核来源 |
| AI 自动出诊断/处置结论 | **不做** | 预问诊摘要按设计不含 `assessment`/`plan`；只有医师在坐诊台填写才算确认 |
| `MEDICAL_LEARNING_AUTO` 生产开启 | **默认关闭** | 自动扫全库产候选会带来噪声；且候选须医师确认 + 人工采纳双闸 |

## 4. 已具备但**不能当成合规证明**的能力

以下都已跑通并有自动化断言，但它们证明的是**工程正确性**，不是临床合规：

- 四角色 JWT + URL 级/资源级双层授权、越权 403、读写双向审计；
- AI 转人工全链路（科室队列 → 接诊 → SSE 双向消息 → 结束落就诊）；
- **医师确认结论采纳闸门**（V5）：就诊带显式 `source`，只有 `PHYSICIAN_CONFIRMED` 的候选可 `approve()`，其余一律 422；演示数据标 `DEMO`，无法冒充；
- LIS MLLP 直连 + HL7 `ACK^R01`（AA/AE/AR），fail closed、幂等、未知患者拒收；
- 自学习候选池 + 审核台 + 版本回滚；
- 一键验证 `run_checks.py --full`（含 MCP stdio、真实就诊评测、分发冒烟）。

> 一句话：**「测试全绿」≠「可以进临床」**。
> 前者说明代码没骗人，后者需要第 2 节的签字。
