# 数据安全协议（Data Security Policy）

> 版本：v0.1（草案，未投产） · 生成日期：2026-11-20 · 适用对象：`pasm-medical` 0.1.1
> 本文回答一个问题：**这个系统的数据是怎么被保护的，哪些已落地、哪些还没有。**
>
> ⚠️ **诚实声明**：这是一份**工程现状协议**，不是合规认证书。文中每一条「已落地」都能在代码里找到对应实现；
> 每一条「未落地」都如实标注。它证明的是工程正确性，**不构成** NMPA 注册、等保测评或 PIA 的替代。
> 配套：`docs/COMPLIANCE-GATE.md`（投产签核清单，代码判不了的资质项）。

## 0. 一句话结论

| 层面 | 状态 |
|---|---|
| 传输加密（TLS/HTTPS） | ❌ **未落地** —— 后端明文 HTTP 8081 |
| 身份认证与授权 | ✅ 已落地（四角色 JWT + 双层授权），但账号源是演示账号 |
| 去标识化（存储侧） | ✅ 已落地（假名化 + 正则兜底），但标注为"兜底非合规方案" |
| 去标识化（出网侧） | ✅ **已落地**（2026-11-20 G2：L1 模板方法统一脱敏 + L4 云端残留拒发），L2/L3 增强未做 |
| 审计留痕 | ✅ 已落地，但与业务同库（生产应独立库） |
| 数据最小化 | 🟡 部分（认知层不存直接标识；全量字段仍在业务库） |
| 合规资质（等保/PIA/器械注册） | ❌ 全部未启动，须机构签核 |

**结论：G2「出网未去标识」已于 2026-11-20 补齐（L1 单点脱敏 + L4 云端硬闸，含中文语境漏网 bug 修复）；缺口集中在「传输加密」(G1) 与账号源/审计同库/合规资质。**

## 1. 数据分类与存放位置

依据 `pasm_medical/domain.py:30-36` 的分层约定：

| 数据类别 | 例子 | 存放位置 | 认知层是否可见 |
|---|---|---|---|
| 直接标识 | 真实姓名、身份证、手机号 | 业务库（Spring Boot / PostgreSQL） | ❌ 不可见、不可存 |
| 间接标识 | `patient_ref`（业务主键/哈希） | 业务库；认知层只拿假名 | 仅以假名形式 |
| 健康数据 | 主诉、现病史、检验值、过敏史、用药 | 业务库 + 认知层（去标识后） | ✅ 可见 |
| 模型输出 | 预问诊摘要、带护栏问答 | 业务库（审计表）+ 认知层 | ✅ 可见，带辅助标记 |

- 认知层 `agent_id` 由 `(机构, patient_ref)` 映射，已做路径穿越防护（`domain.py:27-28,39-51`）。
- 假名化用 `sha256(salt|raw_id)[:16]`（`domain.py:54-62`），**是确定性假名不是加密**，防的是"误写真实标识"，不防穷举。

## 2. 已落地的安全机制（代码可证）

### 2.1 身份与访问
- 四角色 JWT（HS256 签名），身份写在令牌 claim；服务端无状态、可水平扩容（`TokenService.java:17-19`、`application.yml:58-64`）。
- `Authorization: Bearer <token>` 过滤器注入安全上下文（`TokenAuthFilter.java:13-37`）。
- URL 级 + 资源级双层授权，越权返回 403（`SecurityConfig.java:29-48`）。
- LIS MLLP 通道共享密钥校验 + fail closed（`IntegrationTokenGuard.java`、`MllpAuth.java:22-23`）。

### 2.2 去标识化（存储侧）
- `scrub_identifiers()`：手机号/身份证正则替换为 `[已去标识]`（`domain.py:32-40,70-95`）。源码自评："这是**兜底**，不是合规方案 —— 真正的去标识化在数据出业务库之前就该做完"。
  - ★ 2026-11-20 修复真 bug：原正则用 `\b` 边界，而 Python 把中文也算 `\w`，导致「我的手机号是138…」这类**嵌在中文句子里的标识整段漏网**；改用「前后非数字」断言（`(?<!\d)…(?!\d)`），中文语境可命中、长数字串不误截。回归用例见 `domain.py` 自检。
- 记忆写入时调用：`service.py:290` `brief=scrub_identifiers(detail)[:300]`。
- 去标识项目不进记忆，有反例自检（`lab.py:472`）。
- LLM 配置回显时 api_key 强制打码（`llm.py:86-89`、`service.py:756`）。

### 2.5 出网去标识（G2，2026-11-20 已落地）
- **L1 模板方法**：`LLMProvider.complete()`（`llm.py:110`）是出网唯一出口，**先 `scrub_identifiers(prompt)` 再交子类 `_send()`**；子类只能覆写 `_send`，无法绕过。三条出网路径（`phrase_question` / `compose_summary_text` / `compose_answer`）全覆盖。
- **L4 云端硬闸**：`OpenAICompatProvider._send()`（`llm.py:191`）脱敏后再扫一遍 `contains_identifiers()`，仍命中直接 `RuntimeError` 拒发（fail closed），不静默放行。
- **L5 风险回显**：`llm_status()` 返回 `egress.cloud` / `egress.notice`，云端启用时界面可高亮"出网风险"。默认 provider = `null`（不出网）；`ollama` 为本地（不出院）。
- 验证：`llm.py` 自检 25 项（三路径脱敏 + 绕过模板负对照 + L4 硬闸 + 已脱敏不误拦），`domain.py` 自检 19 项；独立端到端反例对照捕获**真实 urllib 出站 body** 确认无原始标识泄漏。
- ⚠️ 边界：L2（姓名/地址/病历号等 NER）与 L3（字段白名单）**未做**，当前正则只覆盖手机号/身份证。云端 provider 上线前仍应按机构合规要求评估是否补 NER。

### 2.3 审计与责任链
- 读写双向审计，带 `model_version` 区分"模型生成"还是"模板拼的"（`llm.py:325-337` 的 `source` 字段）。
- 医师确认采纳闸门：只有 `PHYSICIAN_CONFIRMED` 就诊可 `approve()`，演示数据标 `DEMO` 无法冒充。
- AI 输出统一带"辅助"标记（`safety.py:34`）。

### 2.4 生产自检
- `ProductionGate.java` 启动自检：演示账号、JWT 密钥强度、学习自动开关、MLLP 绑定地址/令牌（:96-117）。
- ⚠️ 自检**不检查 TLS**（无 SSL 相关 check），因为当前版本根本没有 TLS。

| # | 缺口 | 证据 | 影响 |

| G2 | **出网未去标识（已修复 2026-11-20）** | 原 `llm.py` 三条路径原文拼 prompt；现由基类 `complete()` 模板方法统一脱敏 + `OpenAICompatProvider` 残留硬闸，见 §2.5 | 已补 L1/L4/L5；L2/L3（NER/白名单）仍为遗留边界 |

## 4. 数据生命周期规则（当前实践）

1. **采集**：预问诊结构化采集（`consult.py`），直接标识留在业务库。
2. **传输**：❌ 当前明文（见 G1）；院内须靠网络层隔离兜底。
3. **存储**：认知层只存假名 + 去标识文本；全量病历在 PostgreSQL。
4. **使用**：带护栏问答，无来源拒答；LLM 只做措辞不做判断（`llm.py:258-271` ANSWER_SYSTEM）。
5. **出网**：✅ 已补去标识（见 §2.5 G2）——所有 prompt 经模板方法脱敏后再发；云端另有残留拒发硬闸。本地 `ollama`/`null` 不出网。
6. **审计**：读写留痕、模型来源可追溯；同库（见 G4）。
7. **留存/删除**：有 KB purge 能力（`service.py:93,484,490`）；临床留存年限未定义（合规清单第 9 项）。

## 5. 本协议的效力边界

- ✅ **能证明**：工程上实现了哪些保护、缺口在哪、每条对应的代码位置。
- ❌ **不能证明**：等保三级、PIA、NMPA 注册、临床安全有效性——这些只能由机构与人签核（`COMPLIANCE-GATE.md` §0）。
- 🚫 **禁止误读**：把本文件当成"已符合数据安全法规"的证明。它是**现状说明 + 改造清单**，不是合规结论。
