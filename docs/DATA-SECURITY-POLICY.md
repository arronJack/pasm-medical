## 0. 一句话结论

| 层面 | 状态 |

## 1. 数据分类与存放位置

依据 `pasm_medical/domain.py:30-36` 的分层约定：

| 数据类别 | 例子 | 存放位置 | 认知层是否可见 |
|---|---|---|---|
| 直接标识 | 真实姓名、身份证、手机号 | 业务库（Spring Boot / PostgreSQL） | ❌ 不可见、不可存 |
| 间接标识 | `patient_ref`（业务主键/哈希） | 业务库；认知层只拿假名 | 仅以假名形式 |
| 健康数据 | 主诉、现病史、检验值、过敏史、用药 | 业务库 + 认知层（去标识后） | ✅ 可见 |
| 模型输出 | 预问诊摘要、带护栏问答 | 业务库（审计表）+ 认知层 | ✅ 可见，带辅助标记 |

- 认知层 `agent_id` 由 `(机构, patient_ref)` 映射，已做路径穿越防护（`domain.py:27-28,50-62`）。
- 假名化用 `sha256(salt|raw_id)[:16]`（`domain.py:64-72`），**是确定性假名不是加密**，防的是"误写真实标识"，不防穷举。

## 2. 已落地的安全机制（代码可证）

### 2.1 身份与访问
- 四角色 JWT（HS256 签名），身份写在令牌 claim；服务端无状态、可水平扩容（`TokenService.java:17-19`、`application.yml:58-64`）。
- `Authorization: Bearer <token>` 过滤器注入安全上下文（`TokenAuthFilter.java:13-37`）。
- URL 级 + 资源级双层授权，越权返回 403（`SecurityConfig.java:29-48`）。
- LIS MLLP 通道共享密钥校验 + fail closed（`IntegrationTokenGuard.java`、`MllpAuth.java:22-23`）。

### 2.2 去标识化（存储侧）
- `scrub_identifiers()`：手机号/身份证正则替换为 `[已去标识]`（`domain.py:41-95,119-144`）。源码自评："这是**兜底**，不是合规方案 —— 真正的去标识化在数据出业务库之前就该做完"。
  - ★ 2026-11-20 修复真 bug：原正则用 `\b` 边界，而 Python 把中文也算 `\w`，导致「我的手机号是138…」这类**嵌在中文句子里的标识整段漏网**；改用「前后非数字」断言（`(?<!\d)…(?!\d)`），中文语境可命中、长数字串不误截。回归用例见 `domain.py` 自检。
- 记忆写入时调用：`service.py:290` `brief=scrub_identifiers(detail)[:300]`。
- 去标识项目不进记忆，有反例自检（`lab.py:472`）。
- LLM 配置回显时 api_key 强制打码（`llm.py:147-153`、`service.py:756`）。

### 2.5 出网去标识（G2，2026-11-20 已落地；同日补齐 L2/L3）
- **L1 模板方法**：`LLMProvider.complete()`（`llm.py:170`）是出网唯一出口，**先 `scrub_identifiers(prompt)` 再交子类 `_send()`**；子类只能覆写 `_send`，无法绕过。三条出网路径（`phrase_question` / `compose_summary_text` / `compose_answer`）全覆盖。
- **L2 扩展识别模式（2026-11-20 补齐）**：脱敏规则从「手机号/身份证」扩到 **裸值型**（手机号、身份证 18/15 位、座机、邮箱）+ **标签锚定型**（姓名 / 住址 / 地址 / 病历号 / 门诊号 / 住院号 / 证件号 / 出生日期 / 紧急联系人 / 联系电话…）。
  - 标签锚定型**只替换值、保留标签**（`姓名：[已去标识]`）—— 模型仍看得出"这里有个姓名字段"，但拿不到值。
  - 裸值型规则**按长到短排列**：否则短规则会先吃掉长串前缀、留下尾巴（15 位规则先跑会把 18 位身份证截成 `[已去标识]23X`，尾巴反而漏了）。
  - **幂等性是硬约束**：`scrub(scrub(x)) == scrub(x)`，且脱敏后文本不再命中任何规则。否则 L4 硬闸会把"已脱敏文本"误判成残留标识，**云端 provider 永久拒发**。占位符以 `[` 开头且标签型的值部分排除方括号，这是幂等的实现基础。
  - **★ 复盘抓到的真缺陷（2026-11-20，已修）**：标签型的值部分原写作 `{1,200}`，于是「住址：」后面**超过 200 字符的值只脱敏前 200 字，尾巴原样出网**；且残留已不是"标签：值"形态，`contains_identifiers` 检不出、**L4 硬闸也拦不住 —— 静默泄漏**。这跟裸值型"短规则吃掉长串前缀留尾巴"是同一类失败：表面看已脱敏，实际漏了。**修法不是调大数字，而是去掉长度上限**（值本就由分隔符界定边界），并加回归断言"超长值整段脱敏 + 脱敏后无残留"。
- **L3 出网字段白名单（2026-11-20 补齐）**：数据最小化不是"脱敏就够了"，是**根本不发**。
  - 资料侧只允许 `title` / `brief` / `kind` 出网（`EGRESS_ALLOWED_SOURCE_FIELDS`）；`tags` / `salience` / `docKey` / `score` / `patient_ref` 对"把资料说顺"毫无用处，一律不发。
  - 字段级：标识类字段（姓名/电话/住址…）**整条不出网**，而不是只脱敏它的值（`domain.is_identifier_field`）。
  - 长度上限：单字段 600 字符、资料条数 8 条、患者问题（自由文本）500 字符（`EGRESS_MAX_FIELD_CHARS` / `EGRESS_MAX_SOURCES` / `EGRESS_MAX_QUESTION_CHARS`）。
- **L4 云端硬闸**：`OpenAICompatProvider._send()`（`llm.py:251`）脱敏后再扫一遍 `contains_identifiers()`，仍命中直接 `RuntimeError` 拒发（fail closed），不静默放行。
- **L5 风险回显**：`llm_status()` 返回 `egress.cloud` / `egress.notice`，云端启用时界面可高亮"出网风险"。默认 provider = `null`（不出网）；`ollama` 为本地（不出院）。
- **★ 修复 L1 落地时引入的隐缺陷（2026-11-20 实测取证）**：出网 prompt 会被基类脱敏，但**引用核验的基准用的是原始 title** —— 模型看到的是「预问诊·[已去标识]」，核验却拿它比对「预问诊·138…」，导致**模型引用完全正确也被判"编造来源"**，静默降级成原文摘录。无异常、无日志，只有回答质量莫名变差。
  修法不是"核验时也脱敏一下"，而是**让三处共用同一份出网视图**（`_egress_view()`）：prompt 用什么、核验基准就用什么、回退文本也用同一份 —— 一份视图 → 结构上不可能再分叉。
- 验证：`llm.py` 自检 **35 项**（三路径脱敏 + L2 标签型 + L3 白名单/截断 + 引用基准同源 + 负对照 + L4 硬闸），`domain.py` 自检 **37 项**（含幂等断言、超长值不留尾巴、临床文本零误伤）；独立端到端反例对照捕获**真实 urllib 出站 body** 确认无敏感值泄漏、白名单外字段未出网、L4 绕过即拒发零出站。
- ⚠️ 诚实边界：
  - **中文裸姓名与自由文本地址都检不出** ——「我叫张三」「我住在广东省深圳市南山区…」这类**没有标签**的自由文本，L2 无从判定（中文姓名/地址与普通词汇无稳定词形边界，裸匹配必然误伤"李医生"/"当归"/"广东省人民医院"这类临床或机构内容）。L2 只覆盖**标签形态**（「姓名：」「住址：」）。
  - `compose_answer` 的"患者的问题"就是自由文本，因此**只靠值级脱敏兜底**（手机号/身份证/座机/邮箱），并对超长输入按 `EGRESS_MAX_QUESTION_CHARS`（500 字符）截断以收敛暴露面。
  - 真正覆盖自由文本需要**专业 NER**，或**在提问前就把患者信息结构化**（让地址/姓名根本不以自由文本形式进入链路）。
  - L2/L3 是**降低暴露面**，不是"全部 PII 已覆盖"。云端 provider 上线前仍应按机构合规要求评估是否补 NER。

### 2.3 审计与责任链
- 读写双向审计，带 `model_version` 区分"模型生成"还是"模板拼的"（`llm.py:479-491` 的 `source` 字段）。
- 医师确认采纳闸门：只有 `PHYSICIAN_CONFIRMED` 就诊可 `approve()`，演示数据标 `DEMO` 无法冒充。
- AI 输出统一带"辅助"标记（`safety.py:34`）。

### 2.4 生产自检
- `ProductionGate.java` 启动自检：演示账号、JWT 密钥强度、学习自动开关、MLLP 绑定地址/令牌（:96-117）。
- ⚠️ 自检**不检查 TLS**（无 SSL 相关 check），因为当前版本根本没有 TLS。

## 4. 数据生命周期规则（当前实践）

1. **采集**：预问诊结构化采集（`consult.py`），直接标识留在业务库。
2. **传输**：❌ 当前明文（见 G1）；院内须靠网络层隔离兜底。
3. **存储**：认知层只存假名 + 去标识文本；全量病历在 PostgreSQL。
4. **使用**：带护栏问答，无来源拒答；LLM 只做措辞不做判断（`llm.py:354-372` ANSWER_SYSTEM）。
5. **出网**：✅ 已补去标识（见 §2.5 G2）——所有 prompt 经模板方法脱敏后再发；云端另有残留拒发硬闸。本地 `ollama`/`null` 不出网。
6. **审计**：读写留痕、模型来源可追溯；同库（见 G4）。
7. **留存/删除**：有 KB purge 能力（`service.py:93,484,490`）；临床留存年限未定义（合规清单第 9 项）。

## 5. 本协议的效力边界

- ✅ **能证明**：工程上实现了哪些保护、缺口在哪、每条对应的代码位置。
- ❌ **不能证明**：等保三级、PIA、NMPA 注册、临床安全有效性——这些只能由机构与人签核（`COMPLIANCE-GATE.md` §0）。
- 🚫 **禁止误读**：把本文件当成"已符合数据安全法规"的证明。它是**现状说明 + 改造清单**，不是合规结论。
